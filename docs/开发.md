# 开发与发布

本文是开发者向的说明；产品介绍见仓库首页的 [README](../README.zh-CN.md)，调研与设计见 [调研与技术方案](调研与技术方案.md)。

## 开发

```bash
pnpm install          # Node 22+，pnpm 10
pnpm dev              # electron-vite 开发模式
pnpm test             # vitest：解析 / 解压 / 工作区 / 附件 / 更新检查
pnpm typecheck
pnpm pack:mac         # 产出 dist/mac-arm64/Dihua.app（afterPack 钩子做 ad-hoc 签名）
pnpm dist:mac         # dmg + zip
```

微信「转发到其他应用 → 选择电脑中的应用」读取的是 **macOS 系统共享菜单**，所以递话内嵌了一个 Share Extension（`native/share-extension/`，Objective-C，用 Command Line Tools 的 clang 编译，不需要 Xcode）。开发模式下扩展不会登记，必须用打包后的 `.app`：

```bash
pnpm install:mac      # = scripts/pack-mac.sh --install：编译 appex → 打包 → ad-hoc 签名 → 装进 /Applications → pluginkit 启用扩展
```

不开微信也能测：`open -a Dihua fixtures/聊天记录_sample.zip`（走 Finder「打开方式」路径）。

随包有四个共享扩展（`build/share-extension/`，同一份代码、不同 Info.plist）：通用的「递话」（`app.dihua.desktop.share`，弹确认窗），以及「递给 ChatGPT / Claude / Gemini」（`app.dihua.desktop.share.<targetId>`，Info.plist 里带 `DihuaTarget`，点了直接递给该目标，带各自品牌图标）。开哪几个由递话启动时和设置变更时按 `entries.ts` 的规则同步：关掉「入口」→ 全关；开了「收到记录后直接递出去」且有可用目标 → 只开「递给 X」；否则只开「递话」。

若扩展没有出现在共享菜单里：系统设置 → 通用 → 登录项与扩展 → 扩展 → 共享，打开对应条目；或执行 `pluginkit -e use -i app.dihua.desktop.share`（目标入口把 id 换成 `app.dihua.desktop.share.codex` 等）。查看状态：`pluginkit -m -p com.apple.share-services -v | grep dihua`（前面有 `+` 表示已启用）。

## 发布

推一个和 `package.json` 版本一致的标签（例如 `0.0.2` → `v0.0.2`），`.github/workflows/release.yml` 会在 macOS runner 上编译共享扩展、打 arm64 / x64 的 dmg 与 zip（`Dihua-<version>-<arch>.dmg`），并挂到同名 GitHub Release；`ci.yml` 在 push / PR 时跑 typecheck、单测和扩展编译。更新检查按 `src/shared/repo.ts` 里的仓库名找 Release，换仓库时同步改它和 `package.json` 的 `repository`。

```bash
# 改 package.json 的 version，然后
git tag v0.0.2 && git push origin v0.0.2
```

## 在微信里验证

1. 微信任意会话里多选 2 条文字 + 1 张图片 + 1 段视频 → 转发 → 「转发到其他应用」→「选择电脑中的应用」。
2. 子菜单里应出现「递话」，与 AirDrop、Notes 并列。若在「通用 → 投递」里开了「收到记录后直接递出去」，这里会改为列出「递给 ChatGPT」「递给 Claude」「递给 Gemini」（只列已安装且开着的），点哪个就直接递给哪个，不弹确认窗。
3. 选中后递话会弹出投递确认窗。选 ChatGPT：ChatGPT 打开新对话并填好提示词，按回车发送。选 Claude：Claude 桌面端的 Cowork 打开一个新任务，工作区目录已挂上、提示词已填好，接着说要求、回车（第一次会问一次是否信任这个目录）。选 Gemini：transcript.md 和图片作为附件进入 Gemini 输入框，提示词在剪贴板里，⌘V 粘贴后回车。
4. 微信导出的原始 zip 会保留在 `~/Documents/dihua/inbox/<时间>-<会话名>/原始/`。把它复制到本仓库 `fixtures/raw/`（已 gitignore），用来校准 `聊天记录.txt` 的逐行解析规则。

## 界面

全部使用 Ant Design 原生组件与默认主题：设置窗是 `Layout` + `Sider`/`Menu` + `Content`，每个分组是 `Card`，分组里的每一行是 `List.Item`（`Meta` 放标题与说明，右侧放控件），其余是 `Button` / `Switch` / `Select` / `Checkbox` / `Tag` / `Alert` / `Steps` / `Empty` / `Result` / `Collapse`。颜色、圆角、间距都不覆盖，深浅色由 antd 算法跟随系统。`styles.css` 只剩窗口级行为（macOS 标题栏拖拽区、禁止选中、预格式化文本）。页面分区方式（通用 / 入口 / 目标应用 / 记录 / 关于）沿用 Dukou 的信息架构。

递给 AI 时不带任务模板，只预填「记录在哪、是什么」（`src/main/handoff.ts`；ChatGPT 和 Claude 说路径，Gemini 说附件），要做什么由用户到目标应用里自己说。
